# M6 — Reproduction and stability tools

Approved after M5 acceptance (“all works, go next”, 2026-11-11). Stop for human acceptance before M7.

## Result and boundaries

Bugs in the seeded maze become cheap to reproduce. In the F2 debug panel a tester can freeze shift timers, teleport to any room, read a bounded event list and the page-error count, and copy a **bug report**: plain JSON that rebuilds the same maze, replays the same shifts to the same gate poses and puts the player back where they stood. Pasting a report into any build of the same generator version reproduces it, reloading to its seed if needed.

These are developer tools in the opt-in debug panel. M15 removes them from a release build. Reference scenes (`?scene=room`, `junction`, `maze`) are unchanged and get none of these tools.

## Rules

### Run state (`game/generatedRun.ts`)

- `tick`: fixed 1/60 s simulation steps since the attempt began.
- `shiftTicks`: steps the current (or last) shift plan has actually advanced since it was accepted. Reset on each accepted request; not advanced while frozen.
- `events`: last 50 of `shift` (accepted, rejected or ignored request), `freeze`, `teleport`, `visit`, `ring` (walking into a room of another ring), `death`, `return`, `report`. Each has its tick and a readable detail.
- **Freeze** (`setGeneratedRunFrozen`): gate motion and shift timers stop; walking, G requests and everything else continue. A request made while frozen waits in its warning.
- **Teleport** (`teleportTarget`, `teleportGeneratedRun`): only to the centre of a known cell's room, only while alive, and only if the body there overlaps no stone or gate in the current gate poses. Counts in `teleports`, logged, and shown on the return status ("(2 debug teleports)").

### Bug report (`game/runReport.ts`, format 1)

Contents: format, generator version, seed, config, fingerprint; replay inputs (`requests`, `shiftTicks`, `frozen`, `tick`, player x/z/yaw, cell, ring, visits, teleports, crushed gate); expected results (`phase`, `revision`, `completedShifts`, every gate's openness); context for people (last 20 events, shift log, last 10 page errors, browser and window size).

Parsing is strict: invalid JSON, another format, another generator version, another config, out-of-range seed or counts, non-numeric position or malformed visits are refused with a reason.

Reproduction: build the seed's maze; replay `requests` G presses from the starting gates, running every request but the last to idle and advancing the last exactly `shiftTicks` steps (the game's own fixed step). Compare phase, revision, completed shifts and every gate's openness with the report and list any differences. Restore the player's position and view. A crushed body sits inside stone, so it is restored alive in the nearest clear room and that is listed as a difference.

### Loading a report

- **Copy report** shows the JSON in the panel and tries to copy it to the clipboard.
- **Load report** with the same seed applies it in place; with another seed it navigates to `?seed=N#repro=…` and the new page applies it, then removes the hash.
- The pause panel and the tool status line say whether the gate state matched exactly or list the differences.

### Page errors

Uncaught errors and unhandled promise rejections are counted in the panel and included in reports.

## Human acceptance checklist

1. Open the default page: **M6 · REPRO TOOLS**. Press F2. Below the map: config line, tick, page errors 0, Freeze / Copy report, teleport buttons, Events.
2. Press G, then Escape during the warning and click **Freeze shifts**. Resume: the warning does not count down and the HUD says "frozen (debug)". Walk around, then unfreeze: the shift continues.
3. Teleport with **→ Rose**, then by clicking rooms in each ring on the map. The ring label and landmark visits update; the Events list records each teleport.
4. Start a shift and pause mid-closing near the closing gate. **Copy report**. Open another seed with **Random**, paste the report into **Bug report text** and **Load report**: the page returns to the original seed with the same gate half-closed, the same revision and you standing where you were. The message says the gate state matches exactly.
5. Get crushed, Copy report, Retry, Load report: the same gate state returns and you are placed alive in the nearest room, with that noted.
6. Paste broken text or edit `"version"` and Load: a clear refusal, nothing changes.
7. Explore with shifts for ten minutes. Page errors stays 0 and nothing unexplained happens.
8. Spot-check `?scene=maze`, `?scene=junction`, `?scene=room`.

## Automated checks

- `npm ci`, `npm run typecheck`, `npm test`, `npm run test:browser`.
- 40 scripted sessions across four seeds (random walking, G presses, freezes, teleports, up to about 4 400 ticks): report → JSON → parse → reproduce gives identical openness, phase, phase time, revision, completed shifts, plan, requests and position, never inside stone. Coverage check: sessions include mid-shift, completed-shift, frozen and teleported states.
- A crushed session reproduces the gate state and restores the body alive in an adjacent room. A reproduced run continued for 400 steps matches the original continued for 400 steps.
- Freeze leaves shift state untouched and still replays exactly.
- Named scenarios: seed 41 with G7 half-closed after one request; seed 1 after five completed shifts.
- Parsing rejects malformed JSON, non-objects, other format, other version, other config, bad seed, fractional counts, non-numeric position and bad visits; a report for another seed is flagged.
- Teleport: every room centre on three seeds is valid in starting and six-shift gate poses and never overlaps stone; unknown cells and dead players are refused; events stay at 50.
- Production browser: freeze holds a warning past 4 s and shows in the HUD; landmark and map-click teleports update ring, visits and events; a mid-closing report copied on seed 41 and loaded from seed 1 reloads seed 41 with identical revision, G7 openness, position and phase and a cleared hash; a wrong-version report is refused; ten Random seeds in a row rebuild with matching fingerprints and no page errors. All M0–M5 checks.

## Do not build yet

A general replay engine (input recording), telemetry or uploading reports anywhere, a level editor, automatic shifts, objectives or extraction (M7), pressure rules (M7b), art, new dependencies.
