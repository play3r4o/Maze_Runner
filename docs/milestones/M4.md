# M4 — Seeded procedural maze generation

Approved after M3 acceptance (“accepted, go next”, 2026-11-11). Stop for human acceptance before M5.

## Result and boundaries

The default page builds a maze from a numeric seed. The same seed, configuration and `GENERATOR_VERSION` always rebuild the same layout. The maze has a central open Sanctuary plaza, three rings, one landmark per ring and loops, so most places have more than one way home. Walls do not move in M4: generated mazes have no gates until M5.

Reference scenes stay available: `?scene=room` (M0), `?scene=junction` (M1), `?scene=maze` (accepted M2 maze with M3 diagnostics).

## Sizing decision

The plan proposed 13×13 six-meter cells. M2 already fixed 12 m spacing and 4 m corridors so the accepted 8 m crushing passages fit in solid wall pockets, and M5 will reuse those gates. Cells therefore stay at 12 m and the grid size was chosen by measured walking time at the existing 3 m/s, using 200 seeds per option (shortest graph route, Sanctuary to every outer-ring cell):

| Grid | Loop chance | Median one-way | Worst one-way |
| --- | --- | --- | --- |
| 9×9 | 0.10 | 32 s | 88 s |
| **11×11** | **0.10** | **40 s** | **84 s** |
| 13×13 | 0.10 | 48 s | 112 s |

11×11 is the default: an outer-ring round trip plus exploration and wrong turns fits the 3–5 minute prototype target. The footprint is 132 m square. Revisit after M7 playtests rather than enlarging the map for longer runs.

## Generation rules (`simulation/mazeGenerator.ts`)

1. Seed is a whole number 0..4294967295. Text input that is not a whole number in range is rejected and never coerced. RNG is mulberry32; generation never calls `Math.random`.
2. Grid of 11×11 cells with stable IDs `cell-{column}-{row}`. Ring by square (Chebyshev) distance from the centre: 0–1 Sanctuary (9 cells), 2–3 inner (40), 4 middle (32), 5 outer (40). The band formula generalises to other odd sizes ≥ 9.
3. Sanctuary is one open 3×3 plaza: all 12 internal connections exist and its pillars are carved away.
4. Exactly one entrance on each side of the plaza (north, east, south, west), at a seeded position along that side. No other Sanctuary connections.
5. Spanning tree over all other cells: Kruskal's algorithm over every neighbour pair outside the plaza, in canonical order (all horizontal pairs row-major, then all vertical pairs) shuffled by the seeded RNG.
6. Loops: each remaining pair outside the plaza becomes a connection with probability 0.10.
7. Landmarks: Amber Spire (inner), Blue Beacon (middle), Rose Pillar (outer), each in a different quadrant around the plaza.
8. Repair: if any single connection on a landmark's route could cut that landmark off from Sanctuary, add one seeded grid connection between the two sides. Repeat until none remain. This is bounded (one addition per bridge), never a retry loop.
9. Output is sorted plain data plus `serializeMaze` text and an 8-digit `layoutFingerprint`. Bump `GENERATOR_VERSION` whenever a seed's layout could change.

Geometry, collision, rendering and the debug map all derive from that data (`deriveMazeWalls`, `plazaRect`, `corridorRect`, `landmarkRect`). Nothing is placed separately.

## Seed handling

- `?seed=N` reproduces a maze. Without a valid seed the page picks one and writes it into the address, so reloading or copying the URL rebuilds the same maze.
- An invalid `?seed=` shows a message naming the bad value and the replacement seed.
- Debug panel (F2): seed, version and fingerprint; a seed field with **Load seed** and **Random** (both reload the page with the new seed). The fingerprint and seed are also on `<html data-maze-seed data-maze-fingerprint>` for bug reports and tests, and the full serialized layout is logged once to the console.

## Human acceptance checklist

1. Open the default page. Confirm **M4 · SEEDED MAZE** and that the address now contains `?seed=`. The side panel shows the seed and lists three landmarks with their rings.
2. Press F2. Check the map: 11×11 rooms coloured by ring (gold Sanctuary, green inner, ochre middle, red outer), four plaza entrances and the three landmark colours.
3. Walk out of Sanctuary. The side panel ring label changes as you enter inner, middle and outer rooms, and the debug map marker follows you.
4. Visit all three landmarks and return to the plaza without the map if you can; the navigation check reports completion.
5. In the debug panel, Load seed 1, note the fingerprint and layout, then Random a few times, then Load seed 1 again: the same layout and fingerprint return. Inspect at least 20 seeds in total (Random) for readability, odd dead areas or unreachable-looking rooms.
6. Press V with the panel open: the dry run blocks the four entrances and is rejected (112/121 cells lose a route); nothing changes.
7. Try `?seed=abc` and `?seed=-5`: a message reports the bad seed and a random seed is used. Check pause, resize and reload behave as before.
8. Spot-check reference scenes `?scene=maze`, `?scene=junction`, `?scene=room`.

- Three seeds (1, 20261111, 4294967295) physically: spawn and room centres clear; every connection is an 8 m × 4 m corridor; centreline walking passes exactly where the graph has a connection; walking the graph routes with the real movement rules visits all three landmarks and reports the return home.
