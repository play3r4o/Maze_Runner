# M2 — Tiny hand-built maze

Approved after the developer accepted M1 push-before-crush on 2026-11-11. Stop for manual acceptance before M3.

## Result and boundaries

A fixed 5×5 maze of small rooms/junctions, central Sanctuary start, three colored geometric landmarks and two alternating gate shortcuts. Walk out, shift with G, find another route and return. Visit/return feedback is a navigation checklist, not an extraction or loot system.

Use 12 m cell spacing and 4 m corridors so each connection accommodates the accepted 8 m gate passage. Both gates slide 4.5 m sideways into solid pockets. Retain the 2 s warning, 1.25 s replacement opening, 4 s closing, 3 s cooldown, pushing, pinning/death and Retry. Static detours remain connected even with both gates closed. This is a deliberately larger blockout footprint than M4's proposed six-meter cells; review generated geometry sizing at M4 rather than compressing the accepted hazards silently.

## Ordered tasks / expected modules

1. `simulation/maze.ts`: plain cell/edge/landmark descriptors with stable IDs; handwritten adjacent edge pairs; validate IDs/endpoints and connectivity; derive all corridor bounds, solid rectangles, gate poses and landmark colliders from these descriptors. No independent renderer layout.
2. `simulation/movingWalls.ts`: extract the accepted rectangle push/collision routine for use by M1 and M2. Preserve M1 unit/browser regressions.
3. `simulation/mazeShift.ts`: two-gate phase state, timing, busy request rejection and conservative connectivity validation. One shift at a time; only fully open gates count as graph links.
4. `game/mazeRun.ts`: movement, shared pushing, death/Retry and visits/return feedback. Keep plain data and no browser/Three.js imports.
5. `rendering/mazeView.ts`: primitive walls, slabs, danger outlines, Sanctuary marker and three colored landmark pillars/signs, derived from simulation descriptors. Reuse geometry for repeated walls.
6. `main.ts`, `ui/hud.ts`: M2 default and clear instructions/status; retain M0/M1 query scenes; preserve pause, focus loss, pointer lock and graphics fallback.
7. Unit/integration/browser tests, README and progress evidence; publish through the already approved Pages workflow after checks pass.

## Human checklist

1. Open the default page and confirm **M2 · HAND-BUILT MAZE**. Start at the warm Sanctuary marker; movement/look/collision and Escape/resume work.
2. Find the Amber Spire, Blue Beacon and Rose Pillar. Each is a simple colored landmark; visits update only when you reach its room. No map/teleport is required.
3. Press G away from a gate. Observe warning, replacement opening, old closure and cooldown; repeat in reverse. NORTH and EAST shortcuts alternate.
4. Approach a closed shortcut; collision stops you. Find a permanent detour and return to Sanctuary. A changed shortcut must affect your route choice without trapping a region.
5. Enter an open eight-meter passage, trigger its closure, observe the sideways push, try escaping along it, and separately allow yourself to be pinned. Retry resets position, visits, gate arrangement and shift count.
6. Visit all three landmarks and return: the navigation checklist reports completion, and you can keep exploring. Reload starts a fresh attempt; nothing is saved.
7. Pause during warning/closure, switch tabs, resume, resize. No stuck input, unannounced simulation advance while paused or major console errors.

## Automated checks and done criteria

- `npm run typecheck`; `npm test`; `CI=1 PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:browser` locally (omit the executable override on Actions).
- Fixture IDs unique, endpoints valid/adjacent, all 25 cells reachable in both arrangements and during transition, spawn clear, three reachable distinct landmarks.
- For every neighboring cell pair, corridor collision matches the edge/gate state. Walk actual centerline routes through both arrangements and permanent detours; reject nonedges. Gate poses/pockets match the same geometry used by rendering. No living body overlap after pushes.
- Phase order/timing, busy G, all intermediate connectivity, push-before-crush, escape, terminal death and Retry. Landmark visits require physical arrival; central start alone never reports a completed return.
- Production browser: actual controls navigate both shortcut/detour and landmark/return flow, shift warning and changed collision, pause, crush/Retry; no console/page errors. Full M0/M1 regressions remain green.
- Done means runnable production build, passing checks, readable geometry, manual checklist supplied and **developer acceptance recorded separately**. Automated success alone is not human acceptance.
