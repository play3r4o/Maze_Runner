# M1 — Single moving junction

M0 was accepted by the developer on 2026-11-10. Only M1 is approved next; stop for its human acceptance before M2.

## Observable result

Default browser scene is a four-way junction with gold sliding gates. Start at the hub facing NORTH. Initially NORTH/SOUTH are open and EAST/WEST are closed. Press **G** to swap arrangements. A permanent outer loop around four solid quadrant blocks lets every arm return to the hub. Signs and the HUD identify each direction.

The accepted M0 room remains at `?scene=room` for reference and regression tests. Movement, mouse look, pause, tab-switch handling and collision stay unchanged.

## Fixture and authority

- 24×24-meter floor, original outer walls, four solid 6×6-meter quadrants between coordinates ±2 and ±8; corridors and outer loop are four meters wide.
- Stable gate IDs north/east/south/west, centered four meters from the hub; each spans a four-meter corridor, is 0.5 meters thick and three meters high.
- Gates slide 4.5 meters sideways into existing solid wall pockets. Their openness fraction determines the same rectangle for renderer and collision.
- A five-node fixed topology (hub plus arms, with a permanent perimeter cycle) validates return paths; moving gates are conservatively not counted traversable for route validation. No general maze generator or graph framework yet.
- Pure `requestShift` and `advanceShift` own state. Browser input queues one G request; repeats, paused presses, busy requests and cooldown requests cannot restart or queue another shift.

## Timing and safe behavior

1. Validate current/target routes; warn for two seconds. Show a countdown and amber gate cue.
2. Open the two replacement gates over 1.25 seconds.
3. Close the two old gates over 1.25 seconds. Old routes never close before replacement routes are fully open.
4. Cool down for three seconds; wait for the next G press. No automatic shifts.

Before each closing step, inspect the entire gate travel envelope expanded by the player footprint plus a 0.15-meter margin. If occupied, hold both closing gates. If clear within two seconds, resume. Otherwise cancel and reopen all gates, then cool down. **All-open is an explicit safe recovery state, not a completed third arrangement.** G retries the cancelled target after cooldown. No crushing, teleporting or pushing the player.

Advance gates before resolving player movement, using the updated gate rectangles. Recheck safety every simulation tick. Solo pause freezes all phase/obstruction timers and poses. The HUD reports warnings, moving/held gates, completed shifts and rejection/cancellation reasons; console info records holds/cancellations.

## Implementation order and components

Fixture/rectangles → pure shift phases/topology checks → simulation-driven meshes/signs/safety marks → G input/HUD → unit collision/safety cases → real-browser interactions → documentation and deployment.

Main additions: `src/simulation/junction.ts`, `src/simulation/shift.ts`, `tests/shift.test.ts` and `tests/browser/junction.spec.ts`. No new dependencies or physics engine.

## Automated checks

- Phases/timings, opening-first order, exactly-once completion, cooldown and busy/paused input handling.
- Initial/intermediate/final return routes, physical perimeter bypass, repeatable shifts and a two-minute movement/collision scenario.
- Gate poses/colliders agree, thin/partial openings block correctly, early and mid-motion occupancy holds, timeout recovery and clear-area retry.
- Production-browser checks use actual pointer lock/keyboard: blocked gate, warned swap, passage afterward, occupied gate cancellation, and pause freezing shift time.
- Keep all M0 unit/browser regressions. `npm test`; `CI=1 PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:browser` in this cloud machine. Standard Playwright browser command in README applies elsewhere/CI.

## Human checklist

- [ ] Confirm the page says M1; start in the hub. NORTH/SOUTH are open, EAST/WEST closed.
- [ ] Walk both open arms and return. Use the outside perimeter to reach the other arms and return to the hub.
- [ ] Press G: see a warning/countdown, then the new routes opening before old routes close. Gold slabs visibly slide, rather than teleport.
- [ ] Repeat at least ten swaps. Closed gates stop movement; open routes are usable; repeated G/holding G does not queue changes.
- [ ] Stand between the gold lines of an open gate that will close. Request G; it holds, then cancels and reopens everything. You remain free to move.
- [ ] Repeat occupancy checks for different directions and try entering while a gate closes. No crushing/embedding or unexplained movement.
- [ ] Leave a held area promptly: closing resumes. After a cancelled shift, move clear, wait for cooldown, then retry G.
- [ ] Pause during a warning or animation. Wait, resume: no gate jump or elapsed-time catch-up; G while paused has no effect.
- [ ] Mouse/WASD, cursor release/resume, switching tabs and resizing still work. No unexpected console errors.

## Completion and exclusions

Ready for human testing after required automated checks/build pass and visual inspection confirms readable motion. Complete only after the developer accepts the checklist. Exclude random shifts, a full maze, seeds, enemies, loot, audio production, assets, networking, physics replacement and M2 content.
