# M0 — Reliable first-person room

Status/evidence lives in `../progress.md`. M0 was human accepted on 2026-11-10; the current approved milestone is M1. This document preserves the M0 reference specification, available at `?scene=room`.

## Result and exclusions

A start panel opens a gray 24×24-meter room with four walls and a central block. Click Start for mouse look/WASD. Walls stop you. Escape releases the cursor and pauses; Resume continues safely. HUD shows controls, position, and pause state. There is no objective.

Exclude gates, maze generation/topology, interaction, inventory, enemies, art assets, persistence, networking, gravity, jumping, sprint and shadows.

## Fixed defaults

| Property | Value |
| --- | --- |
| Interior | 24×24 m, X/Z ±12 |
| Walls | Height 3 m, thickness 0.5 m |
| Block | Centered at origin, footprint 2×2 m, height 3 m |
| Spawn | (0,8), yaw 0 facing -Z |
| Player | 0.6×0.6 m footprint, 1.6 m eye height |
| Speed | 3 m/s, normalized diagonal |
| Look | FOV 75°, pitch ±85°, no roll, sensitivity .002 rad/unit |
| Simulation | 60 Hz, clamp elapsed to .1 s / six updates |
| Rendering | Basic lit materials, no shadows, pixel ratio ≤2 |

## Components and contracts

Vite, strict TypeScript, Three.js, npm lockfile, Vitest and Playwright. Plain `PlayerState {x,z,yaw}`, `MoveIntent {forward,strafe}`, `WallRect {id,minX,maxX,minZ,maxZ,height}` and pure `stepPlayer(player,intent,walls,dtSeconds): PlayerState`. Pitch belongs to input/camera. No DOM/Three imports in simulation. One set of room descriptors drives meshes and collision.

Expected modules: `src/main.ts` composition; `src/simulation/player.ts` pure movement; `src/simulation/room.ts` fixture; `src/input/browserInput.ts` browser events; `src/rendering/scene.ts` renderer/camera; `src/ui/hud.ts` interface; `src/loop.ts` timing. Tests in `tests/player.test.ts`, `tests/loop.test.ts` and `tests/browser/room.spec.ts`. Supporting package/config/index/style/README files are permitted; no generic framework abstractions.

## Ordered work

1. **A: Visible scene.** Scaffold existing checkout without replacing documents; strict TS/scripts/lockfile; ground/walls/block/camera/lights; resizing; readable WebGL failure. Checkpoint: browser displays room, build works.
2. **B: Input.** User-click Start/Resume pointer lock; physical WASD; yaw/pitch; clear keys and pause on unlock/blur/hiding; reset timing; useful lock failure; avoid page scrolling while controlling. Checkpoint: capture/release works without accidental movement.
3. **C: Movement.** Normalize intent, rotate by yaw, expand rectangles by half-player size, sweep/clamp X then Z for sliding, return new state; fixed-step updates; camera follows state. Checkpoint: walk/slip along walls and around block without penetration.
4. **D: Lifecycle/HUD.** Position/mode/controls; resize/aspect/pixel cap; no catch-up after pause; one loop and handler set. Checkpoint: repeated pause/tab/resize reliable.
5. **E: Verification.** Unit and production-browser tests; run commands; document limits/manual checklist; mark ready for manual testing and stop.

## Commands (repository root)

Use Node 24. Initial package creation uses npm install; subsequent installs use npm ci.

```sh
npm ci
npm run dev
npm run typecheck
npm test
npm run build
npm run test:browser
npm run preview
```

Browser tests build and start a dedicated production preview at 127.0.0.1:4174 with strictPort; never reuse an unrelated process. Default test browser is Playwright's Chromium (`npx playwright install chromium`). An explicit `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` can select an installed compatible Chromium when the managed environment requires it; record which browser was exercised. No silent fallback/skipped checks.

On a local machine open Vite's printed local address. On cloud use the platform's supported access or a browser within the environment; a laptop's localhost is not this cloud machine.

## Human acceptance (not substitutable by automation)

- [ ] Room/controls visible on open; click Start captures mouse.
- [ ] Look in all directions without flip/roll.
- [ ] WASD directions follow view; diagonal speed matches straight speed.
- [ ] All four walls and central block stop movement; no penetration/jitter; oblique movement slides.
- [ ] Escape while holding W pauses/releases mouse; resume without keys has no stuck movement.
- [ ] Switching tabs while moving causes no jump on return.
- [ ] Resize keeps correct proportions; readable HUD remains usable.
- [ ] Repeat in production preview; no unexpected console errors.
- [ ] Record CPU/GPU/browser for future reference performance checks.

## Automated checks

Vitest: idle unchanged; 3 m per simulated second; normalized diagonals; yaw directions; four walls/block; oblique slide; corner blocking; thin-wall tunneling; fixed-tick results independent of render grouping; paused frames do not move; resume discards elapsed pause.

Playwright: production page/canvas/start panel, nonblank rendered content, resize, no unexpected console/page errors. Additional genuine pointer-lock lifecycle checks are useful if supported; they never count as human feel acceptance. Negative WebGL/pointer-lock paths should show useful messages rather than a blank page.

## Done

Automated checks pass, dev and production preview run, manual checks are accepted by the developer, no known collision/stuck-input/pause-jump defects remain, and commands/evidence/limitations are recorded. Until then distinguish implementation from acceptance; do not begin M1.
