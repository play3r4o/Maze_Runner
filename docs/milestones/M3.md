# M3 — Graph validation and visible diagnostics

Approved after M2 acceptance (“all works, go next”). Keep the accepted fixture, movement, gate timings, pushing/crushing, visits, pause and Retry. Stop for human acceptance before M4.

## Build and order

1. `simulation/mazeGraph.ts`: validate stable IDs/endpoints/grid adjacency/start/landmarks; deterministic BFS reachability and shortest cell/edge routes. Fully open gates alone count as links. No Three.js/DOM imports.
2. Use those queries for real shift-plan and intermediate-pose validation. Add a topology revision that increments once whenever the set of fully open connections changes; animation alone, warnings, cooldown and rejected actions do not increment it. A normal swap produces two revisions: replacement becomes fully open, then the old connection becomes unavailable.
3. `simulation/mazeDiagnostics.ts`: pure live view data for player room/passage, conservative route origin, return path, physical gate rectangles and a deliberately invalid isolation probe. No renderer state is consulted.
4. `ui/mazeDebug.ts`: opt-in SVG overhead view, stable cell/edge IDs, moving slab bounds, player position/heading, route and phase/revision/validation status. A scrollable connection list supports inspection while paused. F2 or a button toggles it; V or the probe button runs a dry-run rejection demonstration.
5. Wire input/lifecycle, update M3 labels/docs, verify unit/browser/visual checks and publish using the already approved Pages workflow.

## Diagnostic rules

- Hidden initially. This is a developer tool for comparing graph/collision/rendering, not a final GPS/minimap decision.
- Draw rooms, corridors, landmarks and gates from the same simulation descriptors as the 3D view. Display moving/closed links differently; the route excludes every not-fully-open gate even if a temporary physical gap remains.
- In a static/open corridor, route preview starts at the nearest junction; in a moving/closed gate corridor, show no route preview and explain why. A graph route is not a guarantee of escape before crushing.
- A separate **dry run** proposes blocking all incident Sanctuary connections and displays the validator's rejection, proposed edge IDs and unreachable cells. It never changes walls, gate phases, position, revision or rewards. This demonstrates the same graph validation used by actual shifts without introducing unsafe map editing.
- Pause freezes the simulation. Debug visibility and read-only probing work while paused. Retry clears probe/validation history and resets revision, while keeping the panel's visibility preference for the current page.

## Human acceptance checklist

1. Confirm **M3 · GRAPH DIAGNOSTICS**. Start and walk normally with the debug view hidden.
2. Press F2 (or click **Debug map** while paused). Match nearby corridors, Sanctuary and all three landmark colors to the 3D scene. The player marker follows movement and heading follows mouse look. Read the room/passage ID and inspect the connection list after Escape.
3. Walk north to the next room. With NORTH open the highlighted graph route leads directly home. Press G: observe warning, replacement opening, old closure and changed route. The route must exclude NORTH once it starts closing; use the actual permanent detour to compare both views.
4. Check topology revision: starts at 0, normally reaches 2 after one complete swap, and stays fixed through cooldown/pause. A second swap reaches 4. Gate percentage/physical slab bounds can move without a new revision every frame.
5. With the panel open, press V or click **Probe isolation**. Read the explicit dry-run rejection and proposed edge IDs. Existing passages, shift count, position and revision must stay unchanged; continue walking afterward.
6. Pause/resume, hide/show the panel, resize, deliberately get crushed and Retry. Revision/attempt history reset correctly; prior controls, landmark checklist, and reference scenes remain usable.

## Automated checks / completion

- `npm ci`, `npm run typecheck`, `npm test`, `npm run test:browser` (local managed Chromium override as in README).
- Connected/disconnected/cyclic and malformed fixtures; shortest deterministic routes use existing fully open edges, no phantom endpoint traversal, missing/unreachable targets return no path.
- Actual invalid gate plans retain the original state and provide a reason; intermediate plans remain connected; revision changes match graph changes and never rejected dry runs.
- Pure diagnostic data reflects actual position, route state and slab bounds. Moving-gate occupants never receive a misleading route through the gate.
- Production browser: opt-in toggle, map/position agreement, changing gate/route/revision, rejected probe with unchanged topology, pause and reset; all accepted M0–M2 regressions pass.
- Separate visual check of map readability/geometry alignment. Keep optional milestone images outside clock-controlled functional tests: M2 exposed paused-clock capture stalls. Preserve functional assertions and M0's actual pixel-rendering check.
- Done: tested browser build, recorded evidence and deployment, clear launch/checklist, then developer acceptance. Automated checks do not count as human acceptance.

## Avoid

Seeds, generation/rings, editor controls, unsafe real closures, teleport, automatic shifts, final mapping mechanics, items/extraction economy, enemies/combat, networking, assets, extra dependencies and a general navigation framework. M4 is not approved yet.
